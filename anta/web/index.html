            Flow logs

            One line per connection (Zeek conn.log fields: who, to whom, which application, how much, how it ended), one file per day, readable only by you.

            Rolling capture buffer

            A recorded live capture is written in segments; when a segment is full a new one starts and the oldest beyond the limit is deleted, so the newest traffic is always on disk. Applies to the next live capture.

            Threat intelligence feeds

            Published lists of malicious addresses, domains, URLs, file hashes and TLS fingerprints, kept on this computer. A feed is downloaded only when you press Update; every session is then checked against the enabled feeds as it is analysed, and a match raises a critical alert.

            Detection agent

            Chosen as the detector, the agent reviews sessions the rule detectors didn't flag that go to destinations few of your hosts use. It can look up what ANTA already knows (who else talks to the destination, its DNS names, where it is, threat-intel matches, the conversation's history) and answers malicious, suspicious or benign with its reasons. It only reads: nothing it says acts on the network.

            The address its OpenAI-style API answers at, usually ending in /v1. Plain http:// is allowed only to this computer or your local network; anywhere else needs https://.

            Explain with AI

            Sweep for indicators

            One or more per line, as threat reports print them: IP addresses (optionally with :port), CIDR networks, domains (subdomains match too), URLs, SHA-256 file hashes, JA3 or JA4 fingerprints, and file names written file:name.exe. Defanged forms such as hxxp and [.] are fine. Everything is matched on this computer; nothing is looked up online.

            Results

            Paste indicators and sweep the capture.

            Threat intelligence feeds (checked on every session) are under File → Settings.

            Network rules

            One rule per line, in plain words (block 10.0.0.5 · no ubuntu hosts on the network · don't let router configs be uploaded) or pasted from a firewall (iptables, ufw, pf, Cisco). Every rule is a test (does this capture break it?) and a firewall rule (enforced, what would it block?). Checked as you type; saved rules apply to every capture you open. Nothing touches a real firewall.

            Click an example to add it, then change the address or name. Lines starting with # are notes.

            Device personalities

            Each device on the network in one sentence: what it is, what it mostly does, which way its data flows, whom it talks to. Remember them as normal, and later captures show what each device does differently.

            Ignored alert sources

            Alerts whose source is one of these (an address, a network or a MAC address), of every kind or of one kind, are set aside: they leave the alert list, the stories and What to look at first. Alerts to that address still show. Stop ignoring a source and its alerts come back. The list applies to every capture.
